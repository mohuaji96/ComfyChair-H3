# 剧情组合待修问题

来源：真机 SFW 档抽词结果（2026-11-18 首批 20+ 段）。逐条已核对到代码行，**均未开始修**。

标注含义：`代码` = 要改 StoryGenerator / UI；`数据` = 改 story_catalog_sfw.json 与规则。

## P1 人数被锁死，只能一男一女

- 证据：`StoryComposerScreen.kt:126` `StoryPick("mf", locked = true)`
- 现象：界面「人数」分项永远显示一男一女，点不动，solo / mff / ff 三套模板与池形同虚设
- 修法：`代码`——解锁 CAST，允许四选；切到 solo/ff 时男方三个分项（外形/穿着/穿脱）按空池自动隐藏（B4 的分项过滤已具备该能力）

## P2 「戴着说话前会先停一下」——accent 拼错词

- 证据：`StoryGenerator.kt:696` `else -> "戴着$accent"`
- 现象：口音与说话习惯类词全部套上「戴着」：戴着笑声很轻 / 戴着咬字很清楚 / 戴着喜欢用反问句
- 根因：「戴着」是给配饰（眼镜、耳环）用的前缀，`accent` 池在 SFW 里放的是说话习惯
- 修法：`代码`——按池分前缀。SFW 的 `accent` 直接以句号收尾成独立短句（「说话前会先停一下。」），或改用「，说话时…」

## P3 「体态舒展胸部饱满」——bust 硬编码

- 证据：`StoryGenerator.kt:686-688`
  ```
  bust.endsWith("罩") -> "${bust}杯胸部饱满"
  else -> "${bust}胸部饱满"
  ```
- 现象：每一段女方描述都带「胸部饱满」。SFW 库的 bust 池是「体态舒展 / 肩背平直 / 锁骨清晰」，被硬拼后缀后语义错乱
- 另：`StoryGenerator.kt:41` `StoryField(BUST, "胸部", "bust")`，SFW 下分项名仍叫「胸部」
- 修法：`代码`——按 profile 分支：SFW 只输出 bust 词本身，不加后缀；分项 label 在 SFW 下显示「体态」

## P4 同一个 chore 词在一段里出现两次

- 证据：`StoryGenerator.kt:552`（values["chore"]）+ `:721`（女方段落 `clothes += "此时$chore"`）
- 现象：「此时把椅子拉回原位」在女方段落出现一次，在场景句又出现一次；第二段里男女两方段落各出现一次「此时把毛巾挂在钩上」
- 修法：`代码`——女方段落不再拼 chore，chore 只保留在场景句；或两处取不同池（段落用 detail，场景句用 chore）

## P5 姿势多值用「|」直接拼进句子

- 证据：`StoryGenerator.kt:759` `const val SEP = "|"`
- 现象：「重心落在后脚|双手插兜站着」「双手撑在窗台|回头看向身后」
- 修法：`代码`——渲染前把 SEP 换成「，」；或 SFW 只允许单值姿势

## P6 时间与光线打架

- 现象：正午 + 夕阳照在后颈 / 午后 + 烛光在墙上晃 / 清晨 + 路灯的暖光
- 根因：`light` 与 `time` 之间没有相容规则
- 修法：`数据`——给 light 池标可用时段（skipCategories 或分组），或把强时段词（夕阳、烛光、月光、路灯）从池里拆到带时段的子池

## P7 outfit 词自带鞋，与 shoes 分类重复

- 现象：「针织连衣裙配短靴，白色运动鞋」「黑色针织连衣裙配长靴，米色芭蕾鞋」
- 根因：SFW outfit 池里有「配短靴 / 配长靴」的写法，与 shoes 分类同时出词
- 修法：`数据`——把 outfit 池里的鞋款描述去掉

## P8 穿着与状态自相矛盾

- 现象：「身穿卡其色风衣…外套搭在手臂上」（穿着风衣又搭在手臂）
- 修法：`数据`——`外套搭在手臂上`、`外套半脱搭在肩上` 与「身穿外套」类词互斥，加入 skip 规则

## P9 题材与场景错位

- 现象：「屋顶的消防梯 + 题材：和风町屋」「清晨的厨房 + 题材：沙丘绿洲」「电梯里 + 题材：现代都市」
- 根因：`world` 与 `place` 没有相容规则
- 修法：`数据`——world 与 place 建配对白名单，或把 place 分批挂到 world 下

## P10 场景词自带时间

- 现象：「傍晚，一男一女在清晨的厨房」
- 根因：place 池里有「清晨的厨房」「午后的晒台」这类带时段的名字
- 修法：`数据`——把 place 里的时段词去掉，只留地点

## P11 男方穿脱状态语义偏向女方

- 现象：「此时衣角被风掀起」「围巾松松绕在颈间」出现在男方段落
- 根因：man_state 池沿用了一批中性/女性化状态词
- 修法：`数据`——man_state 换成偏男性的状态（袖口卷起、外套敞开、领口松开、手里拎着东西）

## P12 重抽可能不出新内容（待确认）

- 现象：最后两段文字完全相同
- 需要确认是复制重复还是重抽真的没变
- 若为后者：`代码`——检查 SFW 池在重抽时的候选数，池小于阈值时会回退到同一条

## 第二批（真机第二轮）新增

### P13 剧情库没吃到 B6 的修复

- 证据：`story_catalog_sfw.json` 的 `outfit_state` 仍含 `下摆塞进裤腰 / 裤脚卷起一折 / 衬衫下摆未收`
- 现象：「浅灰针织两件套…衬衫下摆未收」「奶油色开衫配浅色裤…衬衫下摆未收」——身上根本没有衬衫
- 根因：B6 的 patch 只改了 `tag_catalog_sfw.json`，剧情库是另一个文件
- 修法：`数据`——把这三条从剧情池删掉，和标签库对齐

### P14 状态词与实穿对不上

- 现象：`外套敞开` 但穿的是「格纹衬衫配工装裤」，没有外套；`外套半脱搭在肩上` 配「短款羽绒服」
- 根因：`outfit_state` 是独立池，不知道当前穿的是什么
- 修法：`数据`——把依赖外套的状态词与「不含外套的 outfit」做互斥，或改用不指名衣物的状态（衣料微皱、下摆被风吹起）

### P15 chore 与场景错位

- 现象：草地上「把床铺平」、美术馆长廊「在玄关换鞋」、旧车站候车棚「把晾衣绳拉紧」、黑板前「用手掌抹去镜面的雾」
- 根因：`chore` 池与 `place` 没有绑定关系，全局随机
- 修法：`数据`——给 chore 标场景组（室内/户外/居家/工作），place 也标组，同组才配

### P16 「身材身形轻盈」语义重复

- 现象：模板固定写「一位身材{build}的{ethnicity}」，而 build 池里有「身形轻盈」「身量高挑」「体态挺拔」
- 修法：`数据`——build 池去掉自带「身材/身形/体态」主语的词

### P17 bust 池混进姿态词

- 证据：`bust` 池含「坐姿端正」「站姿挺拔」「腰背挺直」「肩膀放松」
- 现象：「坐姿端正胸部饱满」——这是姿态不是体态，而且和「姿势」分项打架
- 修法：`数据`——bust 只留轮廓描述，姿态词归 pose

### P18 place 自带时段（再次确认）

- 证据：`place` 池含 `傍晚的地铁站台 / 清晨的厨房 / 清晨的公交站 / 午后的晒台 / 清晨的烘焙间`
- 现象：「入夜，一男一女在清晨的烘焙间」「周末的懒散上午，一男一女在清晨的烘焙间」
- 修法：`数据`——去掉地点名里的时段前缀

## P12 补充：重抽重复的概率判断

第二批里有两组逐字相同的段落（湖边的小码头、旧车站候车棚）。

核了 `StoryGenerator.randomize(picks, only)`：`only` 为空表示整段重抽，会遍历全部字段重新抽。十几个字段同时抽到完全相同的值，概率上不可能，所以这更可能是**复制粘贴时重复了，而不是重抽失效**。

需要真机确认：点一次「整段重抽」，看是否变化。如果确实不变，再查 `randomize` 的 `allowed()` 是否把候选压到只剩一个。

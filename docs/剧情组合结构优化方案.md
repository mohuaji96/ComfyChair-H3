# 剧情组合结构优化方案

对象：`StoryGenerator.kt`（869 行）、`story_catalog.json`（NSFW 档，30 个池）、`StoryComposerScreen.kt`。
范围：**只谈结构**——叙事连贯性、镜头节奏、动作可执行性。词级错拼（「戴着说话前会先停一下」这类）见 `剧情组合待修问题.md`，不重复。

一句话结论：现在的生成器**写的是一句话，不是一场戏**。它把题材、人物、场景、动作链全部压进一个 `{acts}` 占位符，输出一段连续散文，
没有拍、没有秒、没有镜、没有段末状态。下游的 H3 提示词必须自己把这些补齐，补错的地方就集中在三处：走位缺失、
动作密度失控、通道切换不写抽出。

## 一、现状：生成器到底产出了什么

| 事实 | 位置 |
| --- | --- |
| 出口只有两种形式：`compose()` 把模板填成一段中文，末尾追加「题材：X，画风：Y，有中文台词。」 | `StoryGenerator.kt:509`、`:679-685` |

数量足够，**缺的是它们之间的关系**。

## 二、诊断

### 2.1 叙事连贯性

| 现象 | 根因 | 后果 |
| --- | --- | --- |
| 读起来像清单，不像过程 | 所有动作进一个 `{acts}` 槽，段间只有三句体位级桥接 | 从「站着量三围」到「跪趴插入」中间没有任何走位，下游只能自己编，于是出现「她突然就跪好了」 |
| 第二人像道具 | `outfit_b` 只有穿着，动作池里带 `mff` 的词才是她唯一能做的事 | 她全片只有两种状态：靠在某处、凭空出现在别人嘴边 |
| 段末没有账 | `sceneBefore()` 只用于抽取期过滤，不产出结果 | 跨组衔接只能靠猜，第二组开场常与前组末状态对不上 |
| 一场戏里场景会跳 | 模板整条随机，`place` 跟着重抽 | 同一批设定连抽两次，可能一次在餐桌一次在浴室，前一场的残留没有承接字段 |

### 2.2 镜头节奏

| 现象 | 根因 | 后果 |
| --- | --- | --- |
| 14 秒和 36 秒抽出来的动作数几乎一样 | `pickChain` 固定 2–3 组，与目标时长无关 | 短组塞爆（3 组姿势＋3 个动作＋起手＋换装＋结束 ≈ 8 个动词压进 14 秒），长组空转 |
| 没有镜的概念 | 输出是字符串，无 shot、无时间戳、无镜数上限 | 下游每镜靠猜，全片同景别、同机位 |
| 动作预算无从检查 | 没有「动作动词 ≤ 秒数 × 0.67」「每组 ≤ 6 个动词」这类可计算约束 | 只能事后肉眼发现「太挤」，改起来要重写整段 |
| 细节永远在句尾 | `order` 把 `detail`／`mark`／`mood` 排在 `acts` 之后 | 细节无法分配到每一拍，只能堆在动作全部结束之后 |

### 2.3 动作可执行性

| 现象 | 根因 | 后果 |
| --- | --- | --- |
| 换洞不写抽出 | `act_anal` 独立追加（`:419`），不检查此刻插在哪；词库里已有「手指先探进后穴，再换成阴茎」这种含糊写法 | 一根阴茎同时占两处，或从阴道瞬移到肛门。这是下游反复犯的同一条错 |
| 射精方向与姿势无关 | `act_finish` 12 条直接追加（`:420`），不看她当时趴着还是仰着 | 「弯腰趴桌 + 射在胸口」这类物理错误拦不住 |
| 姿势之间不保证可达 | `pose` 无 `enter`／`exit` 字段，桥接是通用串 | 「站立抱腿」直接「翻过来骑乘」——现实里要先放下腿 |
| 一根阴茎只能在一处，这条约束不存在 | `penetrating` 只影响连接词 | 口交与插入可以并存，抽到什么写什么 |
| 第二人没有接触点 | 动作词条无 `actors`／`contact` | 「另一个人贴着她的脸接吻」这种需要指明谁贴谁的句子，生成器给不出 |

## 三、优化方案

分三层，按依赖顺序落地。每层都能独立上线，不必等前一层完美。

### L1 数据层：给词条补六个字段

`StoryWord` 现有 20 个字段，全部服务于「这个词能不能出现在这句话里」。要让它同时服务「这句话在时间轴上排第几、能不能接上上一句」，补六个：

```kotlin
/** 进这个姿势的走位句。空表示沿用上一拍的结束位置，不需要走位。 */
val enter: String = "",
/** 离开这个姿势的走位句。空表示不需要交代。 */
val exit: String = "",
/** 这一拍的建议时长（秒）。0 按 2 秒算。 */
val seconds: Int = 0,
/** 这一拍占用的通道：vagina / anus / mouth / hand / body / none。 */
val slot: String = "",
/** 换通道时的抽出句。slot 与上一拍不同且上一拍非 none 时必填。 */
val withdraw: String = "",
/** 参与者：f / m / f2。用于一男两女时把动作分派到具体的人。 */
val actors: List<String> = emptyList(),
```

`pose` 池同样加 `enter`／`exit`／`seconds`。`act_finish` 池加两项：

```kotlin
/** 这个收尾要求她当时是什么姿态：趴 / 仰 / 站 / 跪 / 侧。空表示不限。 */
val requiresPos: List<String> = emptyList(),
/** 这个收尾要求阴茎在哪：none 表示必须已经拔出。 */
val requiresSlot: String = "",
```

填法（以既有词条为例，不新增内容，只补关系）：

```json
{ "text": "把她按在桌沿跪下去，腰塌下来", "key": "桌沿跪",
  "enter": "他握住她的腰把她转过去，按在桌沿", "exit": "他把她拉起来转过身",
  "seconds": 3, "slot": "vagina" }

{ "text": "射在她胸口", "casts": ["mf", "mff"],
  "requiresPos": ["仰", "站"], "requiresSlot": "none" }

{ "text": "从后面插进后穴，一手扶着她的胯", "casts": ["mf", "mff"],
  "poses": [], "penetrating": true, "slot": "anus",
  "withdraw": "他把自己从前面抽出来，抵在后穴" }
```

优先级：`act_anal` 8 条与 `act_finish` 12 条先补齐——这 20 条是当前所有物理错误的源头，补完立刻见效。
`pose` 93 条可分批，先补 `common = true` 的那一批。

### L2 生成层：从「拼一句话」改成「排一张拍表」

`compose()` 拆成两段：`buildBeats()` 出结构，`renderBeats()` 出文字。中间产物可被界面编辑、可被校验。

```kotlin
data class Beat(
    val actors: List<String>,       // 谁做
    val pose: String,               // 什么姿势（含 enter 走位）
    val act: String,                // 做什么
    val seconds: Int,               // 几秒
    val slotBefore: String,         // 进入前阴茎在哪
    val slotAfter: String,          // 进入后在哪
    val withdraw: String,           // 换通道的抽出句，无换通道为空
    val contact: List<String>       // 接触点：hand / hip / mouth / penis / table
)
```

**五条新规则**

1. **时长预算**：`buildBeats(picks, targetMs)` 按每拍 `seconds` 累加，到 80% 时开始只收 2–3 秒的短拍，
   到 100% 停止；`finish` 永远保留（超了就丢它前面那一拍）。
2. **动作预算**：每拍 1 个动作动词，总动词数 = 拍数；`拍数 ≤ 目标秒数 × 0.43`（14 秒 → 6 拍）。
   超出时按「删中间、留开头结尾」的顺序删，不随机删。
3. **通道状态机**：维护 `var slot`。`beat.slotAfter != slot && slot != "none"` 时，必先在句首插入
   `beat.withdraw`（缺该字段则拒绝这一拍，退回重抽）。同一时刻只允许一个 `slot`，口交与插入不能并存。
4. **参与者必填**：每个 `Beat.actors` 非空；一男两女时，第二人要么有独立拍，要么在上一拍的
   `contact` 里被明确写出（贴着脸、按着肩），不允许「只在人卡里出现过」。
5. **末状态账**：`endState()` 输出六项——姿态、接触点、光、机位、服装、情绪。这一段就是下一组的开场依据，
   也是下游技能的 `账`。

**镜的合并规则**（渲染时用，不改数据结构）：每镜 1–2 拍，单镜 2–4 秒；
14 秒 ≤ 3 镜，10–12 秒 ≤ 3 镜，7–9 秒 ≤ 2 镜，≤ 6 秒 ≤ 2 镜。相邻镜不得同景别。

### L3 界面层：分拍表 + 预算条

- 抽完不再直接给一段散文，而是给一张表：`拍 / 秒 / 谁 / 姿势 / 动作 / 通道`。每拍可锁、可单换（复用现有 `StoryPick` 的锁与忽略语义）。
- 顶部一条预算条：`已用 12.5 / 14 秒 · 动作 5 / 6 · 镜 3 / 3`，超了标红。
- 「换一条」只换该拍，不再整段重抽——整段重抽会把已经调好的三拍一起冲掉。
- 点「导出」时才 `renderBeats()` 成中文/payload，界面里始终是表。

## 四、优化后的剧本结构排版

这是**给下游技能与 Agent 的交付格式**。现在生成器交一段散文，下游必须自己切；按下面这个形状交，切口就在明处。

### 4.1 六段式

```text
① 规格行   组数 N｜每组 X 秒｜总时长｜模式｜画幅
② 人卡     每个角色一行：外观 + 此刻穿什么 + 此刻在做什么
③ 组表     组｜时长｜只干一件事｜镜数｜拍（带秒数）
④ 分拍表   组内逐拍：秒段｜谁｜姿势（含走位）｜动作｜通道
⑤ 末状态账 姿态｜接触点｜光｜机位｜服装｜情绪（每组一份，末组可省）
⑥ payload  按 ③④ 直译，不再自行增删动作
```

### 4.2 示例（餐桌，2 组 14 秒）

```text
规格：2 组｜每组 14 秒｜总 28 秒｜Ref2VA｜9:16

人卡
F1 御姐：冷白，巨乳，波浪卷发，透明框眼镜，项链。上半身只剩一块布料堆在胸口上方，光腿赤脚。此刻站在餐桌旁量三围。
F2 另一位：清瘦，短发，眉眼浅淡，唇薄。只有黑丝袜与高跟鞋。此刻靠在椅背上看。
M  男人：清爽帅哥，骑士皮甲，腰上围着浴巾，皮甲下面什么都没穿。此刻站在餐桌对面。

组表
| 组 | 时长 | 只干一件事 | 镜 | 拍 |
| 1 | 14s | 打断量三围 → 按跪插入 → 第二人加入 | 3 | 4 / 4.5 / 5.5 |
| 2 | 14s | 换弯腰 → 换通道 → 拔出射胸 | 3 | 5 / 5 / 4 |

分拍表（组 1）
0–4.0    F1           赤脚站在餐桌旁，软尺绕在胸前        —            —
3.0–4.0  M            把腰上的浴巾扯下来扔到地上          —            none
4.0–9.0  M→F1         走过去，把卷发从后颈拨到一边，吻下去  布料被推到胸口上方  none
9.0–14.0 M→F1→F2      把她转过去按在桌沿跪下、塌腰        挺进去        vagina
         F2           从椅子上起身走过来，跪到她脸边      含住她的舌头   —
末状态账（组 1）
姿态：F1 跪趴桌沿、腰塌下去｜接触点：M 双手握腰、阴茎在体内；F2 嘴对嘴｜光：左侧冷窗光｜
机位：侧后方中近景｜服装：F1 上半身只剩布料堆在胸口，赤脚；F2 丝袜高跟鞋；M 皮甲下赤裸｜情绪：动情
```

### 4.3 排版的三条硬规则

1. **一拍一行，秒数写进行首**。拍数由预算算出来，不靠感觉切。
2. **走位独立成拍**。「转过去」「按下去跪」「起身走过来」各占一拍或一拍的前半，不许并进动作句。
3. **换通道单独占一拍**，且必须写明从哪抽出、进哪去。这一拍没有 `withdraw` 就不许出。

## 五、实施顺序与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | `act_anal`／`act_finish` 补 `slot`／`withdraw`／`requiresPos`；生成层加通道状态机与 finish 姿势校验 | 连抽 50 次，不再出现「无抽出的换洞」与「趴着射胸口」 |
| P1 | `buildBeats` + 时长／动作预算 + 镜合并 | 给定 14 秒，产出拍数恒定在 4–6，动词数 ≤ 6 |
| P2 | `pose` 补 `enter`／`exit`／`seconds`（先 common 档），走位独立成拍 | 相邻两拍之间不再出现「姿势不可达」 |
| P3 | 分拍表界面 + 预算条 + 单拍重抽 | 用户可只换一拍而其余三拍不动 |

P0 是止血，量最小、收益最大：8 条 + 12 条数据，加一个状态机。P1 才动生成器主流程，
建议 P0 上线观察一轮再动。
